## 1.4 한계와 남은 일

1. **혜택이 있는 카드가 3장뿐이다.** 추출 → 승인 사이에 정체돼 있다. 대부분의 카드는 "지도에 표시되는 혜택 없음"이다.

3. 삼성, IBK, 카카오뱅크는 robots로 사이트 전체가 막혀 있어 수기 입력 외의 방법이 없다.
4. 실제 간편결제 혜택 0건.
5. 좌표 없는 가맹점 1,213곳, 카카오 좌표 매장 18곳 교체.
6. 토스 승인본 재검토 만료. 이 정책은 승인 후 12시간이라 너무 짧다.
7. 카드 수집 데이터는 10/27 이후 갱신되지 않았다.

| 작업 | 주기 | 로컬 상태 |
|---|---|---|
| 일간 수집 (`daily_crawl_update`) | 매일 00:10 KST | 꺼둠 (`CRAWL_SCHEDULE_ENABLED=false`) |
| 재시도 워커 (`source_retry_worker`) | 5분 | 꺼둠 |
| 정책 검증 배치 (`policy_validation_worker`) | 5분마다 20건 | 꺼둠 |
| 마감 임박 알림 (`daily_deadline_reminder`) | 매일 09:00 KST | 꺼둠 |

**세 작업 모두 같은 스위치를 쓴다.** 로컬에서는 크롤을 꺼두어 10/24 이후 갱신이 없고, 이 때문에 검증도 돌지 않았다.

## 2.4 한계와 남은 일

1. **추천 0건.** 검증이 실행되지 않았거나 실패해서 모든 공고가 `NEEDS_REVIEW`에 머문다.
2. 연결 오류가 자동 재시도되지 않는다.
3. 경희대 공고는 이미지 첨부 하나 때문에 전체가 막히는 구조다. 본문과 주요 첨부를 읽었으면 통과시키고 이미지는 "원문 확인 필요"로 표시하는 방안을 검토 중이다(결정 필요).
4. 장학금 출처가 경희대 한 곳뿐이다. 공고 규모가 19건이다.
5. 마지막 수집이 10/24라 신규 공고가 없다. 만료 처리도 갱신되지 않았다.

# 부록: 수치 재현 방법

모든 수치는 `data/app.db`를 읽기 전용(`mode=ro`)으로 열어 센 값이다. 예:

```sql
select source_platform, status, count(*) from scholarships group by 1, 2;
select source_type, count(*), sum(lat is not null) from local_benefit_merchants group by 1;
select coalesce(issuer,'-'), card_type, count(*), sum(image_url is not null) from cards group by 1, 2;
```
