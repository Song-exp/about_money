# [2026-11-08] 혜택 맵 기획

- **목적:** 혜택 맵의 방향과 확정된 기획을 한곳에 모은다.
- **결정 권한:** 혜택 맵 담당자. 이 문서의 내용은 모두 확정 사항이다.
- **작성 방식:** 새로 정한 것은 해당 섹션을 고치고 "결정 기록"에 날짜와 함께 남긴다.
- **관련:** [카드 혜택 지도 구조도·수집 현황](카드_혜택지도_구조도_수집현황_20261106.md), [데이터 출처·약관 결정 사항](../DB구축/데이터_출처_약관_결정사항_20261106.md)

## 1. 서비스 정의

> **내가 가고 싶은 가게를 찾으면, 내가 가진 결제수단으로 가장 저렴하게 이용하는 방법을 알려준다**

**가장 중요한 원칙:** 기능은 다양해도 **사용 과정은 단순해야 한다.** 처음 설정 이후에는 "가게 검색 → 혜택 확인"만으로 기본 이용이 가능해야 한다.

### 차별화 전략

| # | 전략 | 내용 |
|---|---|---|
| ① | 개인 맞춤형 | 내 카드·간편결제·학교 제휴 혜택만 보여준다 |
| ② | 결제 중심 | 할인율 목록이 아니라 "무엇으로 결제해야 유리한지" 안내한다 |
| ③ | 반복 사용 최적화 | 자주 가는 곳을 저장해 검색 없이 혜택을 확인한다 |
| ④ | 절약 경험 시각화 | 실제 절약액을 마이페이지에 기록한다 |
| ⑤ | 최소한의 조작 | 자동으로 판단하고, 판단할 수 없는 조건만 사용자에게 알린다 |

| 기능 | 방향 | 우선순위 |

| 할인 정보 출처 | 확인일·출처 표시 | 필수 |
| 절약 금액 기록 | 마이페이지와 연동 | 필수 |

## 3. 사용자 흐름

> 사용자 입장에서는 **"가게 찾기 → 혜택 확인"**만 하면 된다. 이미 등록한 정보는 다시 입력하지 않는다.

| 단계 | 사용자 행동 | TMI가 하는 일 |
|---|---|---|
| 최초 1회 | 보유 카드·간편결제·학교 등록 | 맞춤형 혜택 설정 |
| ① 가게 찾기 | 검색하거나 지도에서 선택 | 그 가게의 내 혜택 조회 |
| ② 혜택 확인 | 추천 결제수단 확인 | 할인과 조건 안내 |
| ③ 결제하기 | 실제 결제 | 필요하면 결제 방법 안내 (예: 굿딜 바코드) |
| 선택 | 예상 절약액 계산, ⭐ 저장, 절약액 기록 | 원하는 사람만 이용 |

### 화면 구성

| 화면 | 주요 기능 |
|---|---|
| 지도 메인 | 가게 검색, 내 혜택 표시, 착한가격업소 토글 |
| 가게 상세 | 추천 결제수단, 결제 방법 안내, 할인 조건, 절약액 계산, 저장 |
| 자주 가는 곳 | 저장한 장소 빠르게 조회 |
| 마이페이지 | 보유 결제수단 관리, 절약 기록 확인 |

전체 혜택 탭이나 복잡한 필터는 두지 않는다.

## 4. 처음 가입할 때 (온보딩)

| 받는 정보 | 내용 |
|---|---|
| 보유 카드 | 카드 선택 화면에서 고른다 |
| 사용하는 간편결제·지역화폐 | 토스페이 / 토스 페이스페이 / 카카오페이 / 네이버페이 / 서울Pay+ / 제로페이 / 온누리 |
| 재학 중인 대학교 | 처음에는 경희대만 제공한다 |

- **카카오페이 굿딜은 따로 고르지 않는다.** 카카오페이 앱만 있으면 누구나 쓸 수 있으므로 카카오페이를 고르면 자동으로 포함한다
- **토스 페이스페이는 따로 고른다.** 얼굴 등록이 필요해서 토스페이 사용자라도 쓰지 않을 수 있다

- **받지 않는 것:** 전월 실적, 할인 한도. 사용자가 기억하지 못할 수 있고 입력이 복잡해진다. 필요한 경우에만 상세 화면에서 확인한다
- **학교 인증:** 처음부터 요구하지 않는다. 학교를 고르면 그 학교 제휴 혜택을 보여주고, 학생증 확인이 필요하면 상세 화면에서 안내한다
- **간편결제를 적극적으로 받는 이유:** 카드 데이터가 시드 5장(팀원 DB 37장)뿐이라 지도가 비어 보일 수 있다. 서울Pay+·제로페이 가맹점만 1,140곳이라 카드 데이터가 부족해도 마커가 생긴다

## 5. 지도

### 5-1. 화면

```
🔎 가고 싶은 가게 검색
[⭐ 자주 가는 곳]
[☐ 착한가격업소 보기]

(지도: 내 결제수단으로 할인되는 가게만)
```

| 착한가격업소 토글 | 지도 표시 |
|---|---|
| OFF (기본) | 내 결제수단 혜택 가게 |
| ON | 내 결제수단 혜택 가게 + 착한가격업소 전체 (식당·카페·베이커리) |

- 전체 혜택 탭은 없다. **기본 지도가 내 혜택 지도다**
- 지금 코드의 `resultMode`("혜택 매장" / "가성비 식당" 탭)를 토글로 바꾼다
- 착한가격업소 + 할인 가게는 하나의 마커로 통합한다
- 목록 정렬 기본값은 거리순

### 5-2. 마커

업종 아이콘 + 글자로 구분한다. 색만으로 구분하지 않는다 (색약 사용자 고려).

| 유형 | 마커 예 | 표시 조건 |
|---|---|---|
| 정률 할인, 조건 없음 | `🏪 5%` | 누구나 받을 수 있는 할인 |
| 정률 할인, 조건 있음 | `☕ 10%*` | 전월 실적·한도 등 조건이 붙은 할인 |
| 정액 할인 | `🍽️ 1,000원` | 금액으로 깎아주는 할인 (조건 있으면 `*`) |
| 할인율 미확인 | `🍽️ 혜택` | 혜택은 있지만 할인율·조건이 확인되지 않음 |
| 착한가격업소 | `🍽️ 착한` | 토글 ON |
| 할인 + 착한가격업소 | `🍽️ 10% · 착한` | 두 조건 모두 해당 |

- 혜택이 여러 개면 **내 결제수단 중 가장 유리한 것**을 보여준다
- 숫자는 "최대 할인율"이 아니라 **확인된 할인**이다

### 5-3. 할인율 표시 기준

| 조건 | 조건이 확인됨 | 조건 정보가 없음 |
|---|---|---|
| 할인율·할인액 | 숫자 표시 | `혜택` |
| 전월 실적 | `10%*` (상세에 "전월 30만원 이상") | `10%` |
| 월 할인 한도 | `10%*` (상세에 "월 최대 5,000원") | `10%` |
| 최소 결제 금액 | `10%*` (상세에 "1만원 이상") | `10%` |
| 요일·시간 | `10%*` (상세에 "평일 11~14시") | `10%` |
| 지점 제외 | 이 지점이 제외되면 **표시 안 함** | 표시하고 상세에 "지점별 적용 여부 확인" |
| 유효기간 | 기간이 지나면 **표시 안 함** | `혜택` |
| 중복 적용 | 확인된 조합만 합산 | 합산하지 않고 가장 큰 것 하나만 |

- 사용자의 전월 실적은 알 수 없으므로 실적 조건이 있으면 항상 `*`을 붙인다
- 유효기간을 모르는 혜택은 끝났을 수도 있으므로 숫자를 보여주지 않는다

### 5-4. 상황별 처리

| 상황 | 처리 |
|---|---|
| 지도에 처음 진입 | 내 결제수단 혜택 가게만 표시 |
| 착한가격업소 토글 ON | 착한가격업소 전체 추가 |
| 특정 가게 검색 | 할인 여부와 관계없이 표시 |
| 검색한 가게에 내 혜택 없음 | "**내 결제수단으로** 확인된 혜택 정보가 없어요" |
| 주변에 내 혜택 가게가 없음 | "현재 등록된 결제수단으로 확인된 주변 혜택이 없어요. 보유 카드 정보를 확인하거나 원하는 가게를 검색해 보세요." |

- 혜택이 없을 때 **전체 혜택으로 자동 전환하지 않는다**

## 6. 가게 상세: 결제수단 추천

혜택 목록이 아니라 **"무엇으로 결제하면 되는지"를 가장 먼저** 보여준다. 사용자가 혜택을 직접 비교하게 만들지 않는다.

### 6-1. 첫 화면 (금액 입력 없음)

```
☕ 메가MGC커피 경희대점                ☆ 저장

추천  카카오페이 굿딜로 결제   5%
      결제 방법: 카카오페이 앱 → 굿딜 → 메가커피 바코드 제시

[예상 절약액 계산하기]
[다른 결제수단 비교 ▾]

출처: 카카오페이 굿딜 화면 · 2026-11-08 확인
```

조건이 있는 경우:

```
추천  A 카드로 결제   10%*
      확인 사항: 전월 실적 30만원 이상
```

### 6-2. [예상 절약액 계산하기]를 눌렀을 때

```
결제 금액  [ 12,000 ]원

A 카드로 결제
  예상 절약액        1,200원
  최종 예상 결제금액  10,800원
  확인 사항          전월 실적 충족 여부

[이 혜택으로 결제했어요]
```

### 6-3. 규칙

| 항목 | 규칙 |
|---|---|
| 첫 화면 | 추천 결제수단 + 할인율(또는 할인액) + 결제 방법 안내. **금액은 보여주지 않는다** |
| 절약액 계산 | [예상 절약액 계산하기]를 누른 사람만. 착한가격업소는 대표 메뉴 가격을 미리 채운다 |
| 결제 방법 안내 | 굿딜·페이스페이·학생증 제시처럼 결제 방법이 특별할 때만 보여준다 |
| 다른 결제수단 | 1순위만 먼저 보여주고, 나머지는 "다른 결제수단 비교"를 눌렀을 때 |
| 조건 미확인 | `*`과 확인 사항을 함께 보여준다. 확정 할인처럼 표현하지 않는다 |
| 순위 | 12-5 규칙을 따른다. 전부 조건부면 1순위를 정하지 않는다 |
| 출처 | 모든 혜택에 출처와 확인일을 적는다 |

### 6-4. 할인 정보가 없는 착한가격업소

가격 자체가 혜택이다. 할인율을 만들어 붙이지 않는다.

```
🏷️ 착한가격업소 · 회기 OO식당            ☆ 저장
대표 메뉴  김치찌개 7,000원 (2026-09-30 기준)
착한가격업소 평균보다 1,690원 저렴해요

내 결제수단으로 확인된 추가 할인 정보가 없어요
```

- **가격 비교 기준:** 착한가격업소 같은 업종의 평균 대표 메뉴 가격 (식당 8,690원). 문구에 기준을 밝힌다

## 7. 자주 가는 곳

| 항목 | 기획 |
|---|---|
| 저장 | 가게 상세의 ☆ 버튼 한 번 (☆ 저장 → ★ 저장됨) |
| 조회 | 지도 검색창 아래 "⭐ 자주 가는 곳" 버튼 |
| 혜택 없는 가게 | **저장할 수 있다.** 자주 간다는 이유만으로 저장할 수 있고, 나중에 혜택이 생길 수 있다 |
| 카드 변경 시 | 바뀐 보유 카드 기준으로 혜택을 다시 표시한다 |

```
⭐ 자주 가는 곳
스타벅스 경희대점     A 카드 10%*
CU 경희대점          네이버페이 5%*
학교 앞 음식점        학생증 제휴 혜택
회기 OO식당          확인된 혜택 정보 없음
```

- **저장 기준:** 매장 목록을 상가정보 API로 바꾸면 매장 ID가 바뀔 수 있다. 공공데이터 **상가업소번호**처럼 바뀌지 않는 값으로 저장한다

## 8. 절약 기록 (마이페이지)

| 화면 | 역할 |
|---|---|
| 혜택 맵 | **예상** 절약액을 알려준다 |
| 마이페이지 | **실제** 절약 기록을 관리한다 |

### 8-1. 기록 방법

1. 가게 상세에서 [이 혜택으로 결제했어요]를 누른다
2. 결제 금액과 적용된 할인액을 **사용자가 확인·수정한다** (추천 값이 미리 채워짐)
3. 저장한다

- 버튼을 눌렀다는 이유만으로 할인액을 확정해서 기록하지 않는다

### 8-2. 마이페이지 표시

| 항목 | 예 |
|---|---|
| 이번 달 절약액 | 12,500원 |
| 누적 절약액 | 45,300원 |
| 가장 많이 절약한 분야 | 카페 |
| 가장 많이 사용한 혜택 | A 카드 |

- **이미 있는 것:** 백엔드 절약 기록(`/savings/spend`, `/savings/summary`)과 프론트 호출 함수(`recordSpend`). 원래 금액·최종 금액·절약액·결제수단·매장·분야를 저장한다. 아직 어떤 화면에도 연결되지 않았다

## 9. 표시 원칙

1. **할인은 확인된 경우에만 숫자로 보여준다.** 확인되지 않으면 `혜택`으로 표시한다
2. **조건이 있는 할인은 `*`로 표시한다.** 조건 내용은 상세에서 보여준다
3. **중복 적용은 확인된 것만 합산한다.** 카드 10% + 서울Pay 10%를 임의로 더하지 않는다
4. **"할인 없음"이라고 단정하지 않는다.** 수집되지 않았을 수 있으므로 "확인된 혜택 정보가 없어요"로 쓴다
5. **안내 문구는 "내 결제수단 기준"임을 밝힌다.** 가게 자체에 혜택이 없다는 뜻으로 읽히지 않게 한다
6. **모든 혜택에 출처와 확인일을 적는다.** 착한가격업소 가격도 기준일을 함께 적는다
7. **착한가격업소를 할인율로 바꾸지 않는다.** 가격은 누구나 같고, 할인은 결제수단마다 다르다

## 10. 혜택 수집 범위

> 데이터는 많이 모아도, 사용자에게는 **가장 유리한 결제 방법 하나를 먼저** 보여준다.

### 10-1. 결제수단과 결제 방법을 구분한다

같은 앱이라도 결제 방법에 따라 혜택이 다르다. "카카오페이로 결제하세요"라고만 안내하면 굿딜 할인은 받을 수 없다.

| 결제수단 | 결제 방법 | 따로 관리하는 이유 |
|---|---|---|
| 토스페이 | QR·바코드 결제 | 일반 간편결제 혜택 |
| 토스페이 | **페이스페이** | 사용 방식과 적립 혜택이 다르다. 연결한 카드의 혜택도 함께 적용될 수 있다 |
| 카카오페이 | 일반 결제 | 일반 결제 할인·적립 |
| 카카오페이 | **굿딜** | 상품권 기반 할인. 앱에서 굿딜 → 브랜드 바코드 제시 |
| 네이버페이 | 일반 결제 | 일반 결제 할인·적립 |
| 학생증 | 현장 제시 | 결제수단이 아니라 제시 방식. 카드와 중복될 수 있다 |

### 10-2. 수집 대상

| 혜택 종류 | 수집 | 이유 |

## 11. 혜택 데이터 구조

모든 혜택(카드·간편결제·지역화폐·학교 제휴)을 **같은 형식**으로 저장한다. 그래야 하나의 계산 규칙으로 비교할 수 있다.

### 11-1. 조건은 세 가지 상태로 구분한다

5-3의 "조건이 확인됨 / 조건 정보가 없음"을 구분하려면, 값이 비어 있을 때 **"조건이 없다"인지 "확인을 못 했다"인지** 알아야 한다.

| 상태 | 의미 | 저장 방법 |
|---|---|---|
| 조건 있음 | 출처에서 조건을 확인했고 조건이 있다 | 값을 넣고, `checked`에 조건 이름 추가 |
| 조건 없음 | 출처에서 확인했고 조건이 없다 | 값은 비우고, `checked`에 조건 이름 추가 |
| 확인 안 됨 | 출처에서 확인하지 못했다 | 값을 비우고, `checked`에 넣지 않음 |

### 11-2. 칸 목록

**"지금 코드" 열은 11/8 구현 현황 분석으로 정정했다.** 계산용 조건은 `card_benefits` 테이블이 아니라 `MapEvidence.rules`(`BenefitRules`, JSON)에 이미 대부분 있다.

## 12. 추천 계산 규칙

### 12-1. 입력

| 입력 | 값 |
|---|---|
| 결제 금액 | 사용자가 [예상 절약액 계산하기]에서 입력한 값. 입력 전에는 순위를 정하기 위한 **기준 금액 10,000원**(착한가격업소는 대표 메뉴 가격)을 쓰고, **화면에는 보여주지 않는다** |
| 매장 | 브랜드, 업종, 지점(상가업소번호) |
| 시각 | 지금 |
| 결제수단 | 사용자가 등록한 카드·간편결제·지역화폐·학교 제휴 |

사용자에게 묻지 않는 것: 전월 실적, 이번 달 남은 한도

### 12-2. 혜택마다 판정

| 순서 | 확인 | 결과 |
|---|---|---|
| 1 | 내 결제수단의 혜택인가 | 아니면 제외 |
| 2 | 브랜드·업종이 맞는가 | 아니면 제외 |
| 3 | 유효기간 안인가, 다시 확인할 날이 지나지 않았는가 | 기간이 지났으면 제외 / 기간을 모르거나 확인할 날이 지났으면 `혜택` (금액 계산 안 함) |
| 4 | 이 지점이 제외되는가 | 제외 확인 시 제외 / 지점 조건을 모르면 조건부 |
| 5 | 지금 요일·시간에 되는가 | 아니면 제외 (상세 비교에는 "평일 11~14시만" 안내) |
| 6 | 최소 결제 금액을 넘는가 | 아니면 추천에서 빼고, 상세 비교에 "1만원 이상 결제 시" 안내 |
| 7 | 할인율·할인액을 아는가 | 모르면 `혜택` (금액 계산 안 함) |

결과는 세 가지다. 이름은 기존 계산 모듈과 같다.

| 상태 | 뜻 | 마커 |
|---|---|---|
| `eligible` (확정) | 조건이 없거나 모두 확인되고 충족됨 | `10%` |
| `conditional` (조건부) | 전월 실적·남은 한도처럼 사용자에게 달린 조건이 있거나, 확인 안 된 조건이 있음 | `10%*` |
| `ineligible` (해당 없음) | 위 판정에서 제외됨 | 표시 안 함 |

### 12-3. 절약액 계산

```
정률 할인   절약액 = 결제 금액 × 할인율 (원 단위 내림)
정액 할인   절약액 = 할인액 (결제 금액보다 클 수 없음)
그다음      건당 최대 할인과 월 할인 한도 중 작은 값까지만
```

- **월 한도는 다 남아 있다고 보고 계산하고 `*`을 붙인다.** 이번 달에 얼마나 썼는지는 모르기 때문이다
- 캐시백·적립도 같은 방식으로 계산하되 "나중에 돌려받아요"라고 표시한다. 포인트는 1포인트 = 1원
- **조건부 혜택도 "조건을 채웠다고 가정한" 예상 절약액을 보여준다.** 기존 계산 모듈은 조건이 하나라도 확인 안 되면 금액을 비우는데, 화면에서는 예상 금액이 있어야 비교할 수 있다

### 12-4. 결제수단 하나당 혜택 하나

- 비교 단위는 **결제수단 + 결제 방법**이다. 카카오페이 일반 결제와 굿딜, 토스페이와 페이스페이는 따로 비교한다
- 같은 단위에 맞는 혜택이 여러 개면 **절약액이 가장 큰 것 하나**만 쓴다
- **초기에는 조합을 계산하지 않는다.** 각 결제 방법을 개별로 정확하게 비교한다
- 나중에 조합(페이스페이 + 연결 카드, 카드 + 학생증 등)을 넣을 때는 **양쪽 모두 중복 가능으로 확인된 경우에만** 합산한다

### 12-5. 순위와 추천

| 상황 | 화면 |
|---|---|
| 절약액이 가장 큰 것이 확정 | **추천** 1개 |
| 가장 큰 것은 조건부, 확정도 있음 | **조건 충족 시 추천** (조건부 1위) + **조건 없이 확실한 방법** (확정 1위) |
| 전부 조건부 | 1순위를 정하지 않고 "확인이 필요한 혜택"으로 절약액 순 나열 |
| **결제 금액에 따라 1위가 바뀜** (정률 vs 정액, 한도·최소 금액 경계) | 1위를 정하지 않고 **"결제금액에 따라 달라요"** + [예상 절약액 계산하기] |
| 할인율을 모르는 혜택만 | 금액 없이 혜택 목록만 |
| 해당 혜택 없음 | "내 결제수단으로 확인된 혜택 정보가 없어요" |

**절약액이 같을 때:** 즉시 할인 → 청구 할인 → 캐시백·적립 → 조건이 적은 것 → 이름순

### 12-6. 지도 마커 값

- 내 결제수단 혜택 중 `ineligible`이 아닌 것으로, **기준 금액 10,000원으로 계산한 절약액이 가장 큰 혜택**을 고른다 (기준 금액은 화면에 보여주지 않는다)
- 기준 금액은 **마커 값 고르기와 목록 정렬에만 쓰는 참고용**이다. 가게 상세의 추천을 확정하는 근거로 쓰지 않는다
- 정률이면 `10%`, 정액이면 `1,000원`으로 보여주고, 조건부면 `*`을 붙인다

### 12-7. 나중에 붙일 것

- 절약 기록(8번)이 쌓이면 **이번 달 쓴 한도를 추정**해서 남은 한도를 계산할 수 있다
- 검증된 중복 조합 계산 (12-4)

## 13. 데이터

### 13-1. 화면에 안 보여도 데이터는 모은다

전체 혜택 **탭**이 필요 없는 것이지, 전체 혜택 **데이터**가 필요 없는 것은 아니다. 새 카드를 등록하면 그 카드 혜택이 바로 지도에 반영되어야 하므로, DB에는 다양한 카드 혜택을 계속 확보한다.

### 13-2. 매장 목록을 공공데이터로 확장

```
상가정보 API (상호명 · 업종 · 도로명주소 · 좌표 · 상가업소번호)
   ↓  상호명에서 브랜드 찾기 ("스타벅스 회기역점" → 스타벅스)
매장 목록 (공공데이터 좌표)
   ↓  브랜드로 카드·간편결제 혜택 연결
지도 · 검색 · 자주 가는 곳
```

한 번에 해결되는 것: 매장 확장, 검색, 카카오 좌표 저장 문제, 위치 검증 0곳 문제

### 13-3. 착한가격업소의 숨은 할인 연결

- 착한가격업소 92곳 중 21곳이 서울Pay+·제로페이 가맹점과 주소가 같다 (같은 건물의 다른 가게 포함, 11/8 로컬 DB 확인)
- 주소 + 상호로 연결해서 할인을 붙이고, 연결되지 않을 때만 "확인된 추가 할인 정보 없음"으로 표시한다

### 13-4. 현재 구조의 문제

| 문제 | 내용 |
|---|---|
| DB에 넣어 둔 매장만 표시 | 시드 매장 47곳뿐이라 다른 가게는 할인이 있어도 나오지 않는다 |
| 위치 검증된 매장만 표시 | 검증 기록이 없으면 지도가 비어 있다 |
| 카카오 좌표 저장 불가 | 팀원 DB의 검증된 18곳 좌표를 공공데이터 좌표로 바꿔야 한다 |
| 카드 데이터 부족 | 시드 5장 (팀원 DB 37장) |
| 학교 제휴 데이터 | 경희대만 있다 (학생회 제휴 21곳, 학생 제휴 12곳). 사용자 정보에 학교 칸이 없다 |
| 범위 | 경희대 주변(서울 동대문구)만 다룬다 |
