## 2. 카드사 접근 방식 확인 (2026-11-06)

### 사이트 구조

| 카드사 | 카드 목록이 올라오는 방식 | 수집기를 만들 때의 부담 |
|---|---|---|
| 현대 | 정적 HTML에는 목록이 없고, 페이지가 열린 뒤 상세 조각을 내려받아 채움 | 카드 상세 구조를 따로 분석해야 함 |
| 하나 | 정적 HTML에 거의 비어 있고 스크립트로 채움 | 같은 이유로 새로 분석 필요 |
| 우리 | 내부 JSON POST 요청(`searchListTnBbs.pwkjson`)으로 데이터를 받음 | **사이트 내부 API를 직접 호출**하는 방식이라 일반 페이지 열람보다 위험이 큼 |

세 곳 모두 어댑터를 새로 만들어야 한다.

### robots.txt와 이용약관

| 카드사 | robots (해당 경로) | 이용약관 확인 결과 |
|---|---|---|
| **하나** | 허용 | **제한 조항이 있다.** 이용자가 서비스 정보를 이용해 얻은 정보를 회사의 사전 승낙 없이 복제·유통하거나 상업적으로 이용하는 행위를 금지한다 |
| 현대 | 허용 | 이용약관 페이지(약 5,500자)에서 자동 수집이나 복제 관련 조항을 찾지 못함. 전문 확인은 아님 |
| 우리 | 허용 | 약관 페이지를 찾지 못함 |
| 신한 | (기존 수집기가 준수 중) | 이용약관 페이지의 본문이 열리지 않아 **확인하지 못함** |
| KB국민 | (기존 수집기가 준수 중) | 약관 페이지를 찾지 못해 **확인하지 못함** |
| 토스뱅크 | (기존 수집기가 준수 중) | 위치기반 서비스 약관만 열림. 서비스 이용약관은 **확인하지 못함** |

robots 허용은 약관 허용을 뜻하지 않는다. 거지맵 때와 같은 원칙이다.

### 이미 만든 것에 대한 영향

- **하나:** 카드 3장, Day 카드 이미지 1장, Day 혜택 추출 7개 버전이 위 조항의 적용 대상일 수 있다.
- **신한·KB·토스:** 약관을 확인하지 못한 상태에서 신한 26장(이미지 24장), KB 2장, 토스 2장이 들어와 있다.
- 지금까지는 robots를 지키고 공식 페이지를 한 번씩 읽는 방식으로 수집했다.

## 3. 결정 대기

### 카드 수집 방식 (3단계 현대·하나·우리) — **미정**

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 수기 목록 + 공식 링크 (추천)** | 대학생이 많이 쓰는 카드 20~30장의 이름·카드사·종류·공식 링크를 시드 파일에 직접 입력. 혜택 조건은 공시 상품설명서를 사람이 확인해 입력 | 약관 위험이 작고 구조가 단순함 | 사람이 카드 목록을 정해야 하고 범위가 제한됨 |
| B. 현대·우리 수집기만 개발 | 약관 전문을 먼저 확인한 뒤 어댑터 개발 | 자동화됨 | 작업량이 크고, 내부 API 호출 위험이 남음 |
| C. 보류 | 지금 상태 유지 | 추가 위험 없음 | 카드 목록이 신한 위주로 남음 |

**추천 이유:** 카드 이름·카드사·종류는 사실 정보이고, 자동 수집으로 얻는 이득이 크지 않다. 하나카드처럼 명시적인 제한이 있는 곳은 사용 허락을 받는 쪽이 안전하다.

### 함께 정해야 할 것

- **하나카드 이미지와 하나 유래 데이터를 지금 내릴지:** 추천은 내리는 쪽(공통 디자인으로 대체). 쓰려면 하나카드에 사용 허락을 문의한다.
- **신한·KB·토스 약관 확인:** 본문이 열리지 않은 곳은 직접 열어 확인하거나 카드사에 문의한다.
