# 장학금·청년정책 상담 분리

## 사용자 흐름

하단 `장학금·정책` 안에서 두 상담을 선택한다.

| 상담 | 데이터 | 기본 목적 | 공고 선택 |
|---|---|---|---|
| 장학금 상담 | 대학·재단 등 장학 공고, 청년정책 API 자료 제외 | 장학금 탐색 및 검토된 양식의 신청서 작성 | 기존 장학금 작성 흐름 |
| 청년정책 상담 | 온통청년 API와 정부혜택 자료 | 지원 대상·내용·준비 서류·신청 방법 확인 | 정책 상세 조회, 공식 원문 확인 |

정책에 글이나 서류가 필요한 경우에는 원문 요구를 설명하지만 모든 정책을 자기소개서 작성으로 유도하지 않는다. 정책 상담에는 과거 장학금 신청서 첨부와 장학금 작성 진입 UI가 없다.

## API와 데이터 경계

- 장학금: `/chat/message`, `/chat/session`.
- 청년정책: `/policy-chat/message`, `/policy-chat/session`.
- 상담 종류는 API가 결정한다. 모델 답변이나 클라이언트 본문으로 조회 범위를 바꿀 수 없다.
- DB 테이블은 기존 구조를 공유하되 `consultation_scope.py`의 출처·분류 조건으로 논리적으로 격리한다. 장학금 제목이 포함되어도 온통청년 출처는 정책 범위다.
- 검색뿐 아니라 상세·비교·선택에서도 범위를 확인한다. 정책 자료는 양식이 과거 검토된 경우라도 장학금 작성 가능 대상으로 취급하지 않는다.
- 대화 저장 payload의 상담 종류로 최근 대화를 따로 복원한다. 다른 상담의 세션 ID를 재사용하면 409로 거절한다. 기존 미분류 통합 대화를 새 상담에 자동으로 섞어 복원하지 않는다.

## 수집 및 기존 데이터

- 온통청년 어댑터는 제목의 `장학` 키워드로 장학금 분류를 만들지 않는다. 이후 upsert에서도 분류를 갱신한다.
- 신청 기간 구분·신청 시작/종료를 사업 기간과 별도로 보존한다. 기간을 모르면 unknown으로 표시하고 수정일이나 사업 종료일을 신청 마감으로 표시하지 않는다.
- 원문이 상시라고 보고한 경우와 날짜가 없는 경우를 구분한다. 별도 원문 확인 없이 현재 접수 가능을 확정하지 않는다.
- 분류 정리 스크립트: `python -m app.scripts.separate_consultation_sources --apply`.
- 로컬 SQLite 백업 후 정책 출처의 기존 오분류 8건을 GOV_BENEFIT으로 옮겼다. 공고 ID·본문·사용자 이력은 삭제하지 않았다. 현재 DB 분류는 장학금 6건, 정책 826건이다. 이는 수집 건수이며 현재 모집 중 건수가 아니다.

## UI 보호

- 기존 페이지 폭·색·채팅 패널을 유지하고 상단에 상담 선택 영역을 추가했다. 관련 CSS는 consultation 클래스 아래로 제한했다.
- 모바일에서는 긴 제목과 조건을 줄바꿈한다. 기간 확인 상태는 모바일에서도 본문에 표시한다.
- 상담 전환 시 컴포넌트 상태를 분리하고 해당 API에서 이전 대화를 불러온다. 응답 중에는 전환을 잠가 이전 응답이 새 상담에 섞이지 않게 했다.
- 작성 중 URL이 정책 상담으로 넘어가지 않도록 전환 시 writing_session을 제거한다.

## 검증 범위

- API 단위 검증: 서로 겹치지 않는 검색 집합, 기존 오분류의 안전한 조회 분리, 상담 간 세션 재사용 차단, 각각의 대화 복원, 정책 선택의 상세 조회 전환, 장학금 작성 차단, 이후 수집 시 분류 갱신.
- 브라우저: 상담 전환·복원·새로고침, 정책 상세의 실제 API 호출, 신청서 작성 호출 없음, 첨부 UI 분리, 390px·360px 가로 넘침 없음. 임시 DB의 합성 공고로 UI 동작을 검사했으며 실제 정책 접수 가능 판정이 아니다. 데스크톱·모바일 캡처는 `reports/consultation-split-20261024/`에 있다.
- 기존 장학금 작성 및 지도 브라우저 회귀도 실행했다. 지도 SDK 실연결 검증 모드는 기존 정책에 따라 별도 skip한다.
- 실제 로컬 API와 DeepSeek 점검에서 청년정책 상담은 서울의 주거 지원 정책 2건을 반환하고 writing selection은 null이었다. 장학금 상담은 정책 자료를 반환하지 않았다.
- 최종 전체 회귀: **2,085개 통과**. 중간 점검에서 발견한 공통 양식 검증과 상담 분류의 결합을 제거하고, 실제 작성 API·서비스 진입점에서 정책 작성을 차단하도록 수정한 뒤 전체를 재검증했다.
- 최종 브라우저: **6개 통과, 실제 지도 SDK 모드 1개 기존 조건에 따른 skip**. 신규 상담 전환과 기존 정보 상담·장학금 작성·지도 흐름 포함.
- TypeScript 타입 검사·Vite 빌드·변경 파일 공백 검사 통과. 로컬 프런트와 API health 모두 HTTP 200.

## 남은 범위

이 변경은 상담·조회 파이프라인 분리다. 외부 자료 재수집, 각 기관의 현재 접수 확인, 전국 실시간 검색 또는 정책 전용 문서 작성 기능을 추가한 것은 아니다. 장학금 수집 자료의 검토 상태도 임의로 승인하지 않았다.
