# 청년정책 API 원문 대조 파이프라인

## 구현 범위

공식 온통청년 API 원문 텍스트와 추출된 요건·정형값을 대조한다.
신청 사이트/지자체 PDF를 별도로 방문해 확인한 상태, 사람의 최종 검수,
개인의 신청 자격 충족 확정과는 구분한다. PDF/OCR은 이 경로에 사용하지 않는다.

### 수집과 보관

- 설명·지원내용 외에 나이, 혼인, 취업, 학력, 전공, 소득 범위/기타 조건,
  참여 제한, 신청기간, 사업기간, 방법, 서류, 선발·기타사항을 포함한 전체 API 응답을 보관한다.
- `source_documents`에 `policy_api_response`(전체 응답 JSON), `policy_api_text`
  (정규화한 조건·검증용 텍스트)를 보존하고 해시와 수집 시도에 연결한다.
- 공식 검색 화면의 input/option 코드명을 파싱하며 소득·연령 표시 로직의 원문도 보관한다.
  의미를 알 수 없는 코드나 잘못된 범위는 추측하지 않고 검토 필요로 분류한다.
- 조회수·등록/수정 시각만 바뀌면 같은 요건의 검증을 무효화하지 않는다.
  조건·기간·본문·디코딩 값이 바뀌면 기존 통과 상태를 무효화한다.

공식 코드표 출처: https://www.youthcenter.go.kr/youthPolicy/ythPlcyTotalSearch

코드표 파일: `data/youth_policy_codes.json`.
원본 HTML 및 적용 코드표 해시는 실행 보고서/정책 source 메타데이터에 보관한다.

### 검증과 분류

1. 수집된 정책은 `policy_validation.status=pending`으로 대기열에 넣는다.
2. 전체 검증용 텍스트를 최대 6,500자 조각(1,000자 겹침)으로 빠짐없이 처리한다.
3. LLM이 자격·제외·혜택·기간·방법·서류·선발·의무를 목록화한다.
4. 모델은 인용문을 다시 쓰는 대신 API 필드 ID를 선택한다.
   코드가 보관 JSON에서 해당 필드의 텍스트·문자 위치를 찾아 근거를 붙인다.
   존재하지 않는 필드, 숫자 변경, 원본 해시 불일치, 매핑되지 않는 텍스트는 차단한다.
5. 별도 LLM 호출에서 전체 원문과 요건 목록·저장값을 대조한다.
   모든 요건 ID의 검토 응답과 모든 원문 조각의 검사 범위를 확인한다.
6. 누락·불일치·불명확·모델 장애·잘못된 응답은 `needs_review`와 상세 사유로 저장한다.
   전부 통과한 경우만 `passed`다. 같은 제공 모델을 별도 호출하는 자동 대조이며 무오류 보장은 아니다.
7. 검증 중 원본이 변경되면 이전 내용으로 판단한 결과를 저장하지 않는다.

버전: `policy-api-text-v3`.

`eligibility.policy_validation`에 버전, 범위, 지문, 요건/근거, 검사 범위,
누락·불일치 및 처리 오류를 저장한다. `scope=official_api_text`다.
검증 상태와 모집 상태는 별개다. 내용이 맞아도 마감됐으면 모집 중으로 안내하지 않는다.
통과 여부는 검색/상담 시 지문을 다시 확인한다. 추가·제외 조건은 개인 적격 확정으로 바꾸지 않는다.

### 상담과 운영

- 미검증/대기/검토 필요 정책은 검색·상세 도구·첫 문진 후보에서 제외한다.
- 검증된 정책이 없으면 수집 건수와 검증 대기 상태를 안내한다.
- 검토 큐 API에 정책 검증 결과를 노출한다. 정책을 신청서 양식 검수 대상으로 취급하지 않는다.
- 기본 배치는 20건이며 일간 수집 후 한 배치를 처리한다.
- 수집 스케줄이 켜져 있으면 공유 작업 잠금을 사용하는 별도 검증 작업이 300초마다 대기열을 처리한다.
- 로컬의 자동 수집 설정은 켜지 않았다. 이 설정에서는 수동 명령으로 계속 처리해야 한다.
- `needs_review`는 자동으로 반복 승인 시도하지 않는다. 원인 보완 후 `--retry`로 재검증한다.

설정: `POLICY_VALIDATION_BATCH_SIZE=20`, `POLICY_VALIDATION_INTERVAL_SEC=300`.

## 수동 실행

DB 읽기 및 건수 확인:

`python -m app.scripts.validate_youth_policies --output <새 보고서 폴더>`

SQLite 백업 후 최신 코드표/API 수집 및 최대 20건 검증:

`python -m app.scripts.validate_youth_policies --output <새 보고서 폴더> --apply --refresh --limit 20`

보관된 전체 API 응답을 새 디코더로 재해석하고 검증:

`python -m app.scripts.validate_youth_policies --output <새 보고서 폴더> --apply --rebuild-archives --limit 20`

이 재해석은 기존 수집 시각을 보존하며 새 API 수집으로 표시하지 않는다.

특정 정책 재검증:

`python -m app.scripts.validate_youth_policies --output <새 보고서 폴더> --apply --ids 31 32 --retry --limit 2`

최신 수집에 실패하면 기존 자료를 갱신한 것으로 표시하지 않고 해당 실행의 후속 검증을 건너뛴다.
보관 자료 검증은 별도 명령으로 실행한다.

## 실제 처리 결과 (2026-10-27)

- 전체 정책 2,644건 중 전체 API 원본이 있는 2,635건을 재해석했다. 기존 수집일은 10월 24일이다.
- 나머지 9건은 전체 응답 원본이 없는 기존 미검증 자료다.
- 동일 표본 5건의 최종 결과: 통과 0, 검토 필요 5.
  2건은 지역/학력/신청 절차 등 내용 대조의 미해결 사항,
  1건은 검증 응답 형식 오류, 2건은 모델 연결 오류다. 처리 장애를 내용 오류로 확정하지 않았다.
- 최종 DB: passed 0, needs_review 5, pending 2,630, unverified 9.
- 검증 통과 상담 후보는 현재 0건이다. 전체 2,644건의 검증이 완료된 것은 아니다.
- 10월 27일 전체 API 갱신 시도는 HTTP 400으로 실패했다. 이후 최소/500건 요청은 성공했으나,
  이를 전체 갱신 성공으로 해석하지 않았다. 위 검증은 보관 원본 기준이다.
- 적용 전 SQLite 백업을 생성했다. 경로는 각 실행 보고서에 기록했다.

최종 실행 기록: `reports/policy-validation-20261027-v3/result.json`.
이전 v1/v2 결과는 진단 과정이며, 최종 버전 결과와 섞어 통과율을 계산하지 않는다.

## 검증

전체 Python 회귀 테스트 통과. 추가 정책 검증 테스트는 전체 필드 보관, 미검증 차단,
정상 통과/누락 보류, 근거 위조·숫자 변경 차단, 원본 무결성, 버전/내용 변경 무효화,
배치 상한, 모델 장애, 원본 재해석 시 수집 시각 보존, 검증 도중 변경 차단을 포함한다.
상담 전환·복원·첫 문진·모바일 브라우저 테스트 및 TypeScript/Vite 빌드도 확인했다.
