# 장학금 빈 결과 진단 및 청년정책 공고 기반 문진

## 로컬 DB 진단 (2026-10-24)

- 연결 정상: 전체 832건, 장학금 상담 범위 6건, 청년정책 826건.
- 장학금 6건 모두 NEEDS_REVIEW. 마감 경과 2건, 마감 미확인 2건(중복 집계).
- 최근 수집 2026-09-28, CRAWL_SCHEDULE_ENABLED=false.
- 6건의 최근 SourceFetchAttempt 모두 partial. 첨부의 structured_validation_failed,
  일부 이미지의 ocr_required가 원인이다. DB 연결 실패가 아니다.
- 청년정책 826건은 이전 수집본으로 application_period 메타데이터가 없다.
  최신 수집 어댑터는 이를 저장하지만 기존 레코드는 재수집 전까지 미확인이다.
- 검토 상태를 임의로 OPEN으로 바꾸거나 오래된 데이터를 현재 모집으로 승인하지 않았다.

장학금 무결과 응답은 DB 저장 수와 검토·마감 제외 수를 코드에서 직접 표시한다.
양식의 복잡한 구조화 실패가 공고 전체를 partial로 만드는 기존 수집 동작은 남아 있다.
수집 재개, 원문/첨부 재처리 및 공고 사실 검증과 양식 검수의 분리가 후속 과제다.

## 청년정책 문진

1. 청년정책 탭에서 복원할 대화가 없으면 POST /policy-chat/session으로 첫 문진을 생성한다.
2. DB에서 정책 범위를 강제하고 검토 상태, 명시된 신청 시작/종료일을 검사한다.
3. 관심 키워드와 대화 맥락을 우선해 최대 32개 공고 본문을 LLM에 전달한다.
   첫 문진은 목록의 여러 위치에서 자료를 골라 분야 편중을 줄인다. 이전 후보 최대 8개를
   포함해 번호 선택 및 후속 질문의 맥락을 유지한다. 전체 정책을 모두 분석했다는 뜻은 아니다.
4. LLM이 본문 조건에서 최대 3개 질문과 관련 자료를 제안한다. 고정 학점·소득분위 문진은 없다.
5. 코드가 공고 ID, 정확한 본문 인용, 질문의 수치 근거를 검증한다.
6. 질문, 답변, 후보, 근거를 기존 소유자별 대화 저장소에 보관한다. 복원 후에도 이어진다.
   계정의 장학금 프로필에 주거 형태·진학 계획을 덮어쓰지 않는다.
7. 이전 질문과 사용자 답변을 다음 턴에 전달해 추가 조건을 확인한다. 질문 선택·관련도 판단은
   LLM 역할이며 코드가 복잡한 정책 자격의 최종 적격 판정을 내리는 것은 아니다.

신청 기간이 현재에 해당하며 7일 내 수집한 자료, 또는 7일 내 수집한 상시 신청 자료만
현재 기간에 해당하는 것으로 구분한다. 이 역시 잔여 예산·접수 조기 종료까지 확인한 보장은 아니다.
날짜 누락, 오래된 수집본은 사전 상담 자료로 표시한다. 명시된 종료/미시작 기간은 문진에서 제외한다.
LLM 실패 시 질문을 지어내지 않고 실제 공고와 연결 실패 안내를 표시한다.

## 검증

- 실제 로컬 API + DeepSeek 첫 질문/후속 답변 확인: 주거·대학원 관심 → 거주 형태/진학 질문,
  서울·25세·재직·월세·진학 예정 답변 → 주택 전용면적/대학원 전공 추가 질문.
- 자동 테스트: 질문 근거 위조 차단, 기간/신선도 검사, 장학금 프로필 필터 미적용,
  대화 복원, 두 상담 범위 분리, 빈 결과 집계.
- 브라우저: 첫 입력 전 문진, 상담 전환/복원, 정책 상세, 모바일 가로 넘침 검사.
