# 수집 시 공고 원문 대조 검증

## 동작

경희대 장학공지 수집 및 해당 플랫폼의 보관 원문 재처리에 적용한다.
청년정책 API는 이 PDF/OCR 검증 경로를 사용하지 않는다.

1. 본문·첨부 원본을 다운로드하고 바이트/해시/추출 텍스트/파서 상태를 보관한다.
2. 직접 텍스트/OCR 추출 실패, 저신뢰 경고, 원본 누락, 해결되지 않은 외부 링크가 있으면
   문서별 사유를 남기고 검토 필요로 분류한다. 구조화 오류로 error 필드가 덮여도 ocr_error를 확인한다.
3. 읽을 수 있는 모든 원문을 최대 6,500자, 1,000자 겹침으로 나눠 전체 범위를 처리한다.
4. LLM이 자격/제외/혜택/기간/방법/서류/선발/선정 후 의무를 요건 목록으로 만든다.
   코드가 원문 인용과 숫자 근거를 검사하고 파일 해시·문자 위치·페이지/블록을 연결한다.
5. 별도 LLM 호출에서 원문과 요건 목록·정형 저장값을 대조한다. 누락된 조건, 잘못된 값,
   표의 대상-금액 관계, 예외/중복수혜, 마감 시각, 일정 충돌 등을 검사한다.
6. 모든 요건 ID의 검토 응답과 모든 원문 조각의 처리 완료를 확인한다.
   누락/충돌/잘못된 응답/모델 장애는 검토 필요다. 모델 연결 없이 자동 통과시키지 않는다.
7. 문서 대조 통과이고 마감일도 확인되면 OPEN 또는 CLOSED로 분류한다.
   통과 전의 읽기 실패·미해결 항목은 NEEDS_REVIEW로 저장하며 검색에서 제외한다.
   문서 내용은 통과했어도 신청 기간을 확정할 수 없으면 NEEDS_REVIEW다.

별도 검증 호출은 같은 제공 모델을 사용한다. 이는 자동 검증 통과이며 사람의 독립 검수나
모든 누락이 수학적으로 없다는 보장은 아니다. 접수 상태/개인 적격 여부와도 구분한다.

## 저장 및 무효화

`eligibility.document_validation_required=true`, `eligibility.document_validation`에
버전, status(passed/needs_review), 검사 시각, 원본/값 지문, 문서별 검사 범위,
요건 목록과 출처, 누락·불일치·읽기 실패 사유를 저장한다. 기존 JSON 컬럼을 사용한다.

새 수집에서 통과 결과 캐시는 원본 바이트·파서 버전·추출문·저장값 지문이 같을 때만 재사용한다.
검색 시에도 본문·주요 자격·금액·마감·서류·content_hash를 다시 비교해 변경된 값을 차단한다.
첨부 재다운로드 실패 시 기존 읽을 수 있던 데이터는 보존하고 검증 결과와 상태를 변경한다.
최초 실패도 검토 레코드와 원본 기록을 남긴다.

원문 정보 대조가 통과하면 양식 구조화 오류만으로 검색·상담을 차단하지 않는다.
신청서 자동 작성은 기존 양식 검수/지문 및 구조화 오류 검사를 계속 통과해야 한다.
요건 목록은 채팅 후보의 source_requirements에도 전달한다. 추가·제외 조건은 자동 적격 판정으로
바꾸지 않고 확인 필요로 안내한다. 검토 큐 API에는 document_validation을 포함한다.

## 현재 데이터 및 검증

- 기존 로컬 장학금 6건을 보관 자료 기준으로 대조하고 결과를 DB에 적용했다.
  모두 PDF/OCR 충돌·저신뢰 또는 이미지 해석 문제로 needs_review다.
- 적용 전 SQLite 백업을 생성했다. 백업 경로와 건별 결과:
  `reports/scholarship-document-validation-20261024-final/result.json`.
- 이는 신규 사이트 재수집이 아니다. crawled_at은 갱신하지 않았다.
- 실제 DeepSeek로 산재 모집 안내문 PDF 하나만 별도 검증했다.
  요건 54개(자격 7, 제외 3, 혜택 4, 방법 2, 기간 1, 서류 17, 선발 10, 의무 7, 기타 3),
  원문 조각 1개를 대조해 passed를 반환했다. 이는 부속 포스터·이미지를 포함한 공고 전체 승인이 아니다.
  이 실험 결과는 DB에 승인값으로 적용하지 않았다.
- 누락/불일치/가짜 인용/검토 ID 누락/모델 장애/전 원문 범위/캐시 무효화/수집 분류/
  양식과 공고 상태 분리를 자동 테스트한다.

실행:

`python -m app.scripts.audit_collected_scholarships --output <새 폴더>` (DB 읽기 전용)

`python -m app.scripts.audit_collected_scholarships --output <새 폴더> --apply`
(로컬 SQLite 백업 후 상태/검증 결과 저장, 사이트 재수집 아님)

기존 수집 기록을 최신 파서까지 다시 처리하려면 기존 관리자 원본 재처리 API를 사용한다.
현재 PDF 파서의 '이미지가 있으면 페이지 전체 추가 OCR' 동작은 여전히 남아 있다.
이 때문에 정상 텍스트가 있는 자료도 보수적으로 검토 필요가 될 수 있으며, 영역별 OCR 개선은 별도 작업이다.
